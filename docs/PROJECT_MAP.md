# Карта проекта StudyTracker

Короткий маршрут для разработчика или агента. Пользовательский сценарий и запуск описаны
в [README](../README.md). Эта карта описывает текущий код; [GAMIFICATION_SPEC.md](../GAMIFICATION_SPEC.md)
содержит исходный замысел геймификации, часть которого уже реализована.

## Устройство приложения

Electron + React 19 + TypeScript. Интерфейс использует Tailwind CSS 4 и Recharts 3.
SQLite через `better-sqlite3` хранит данные локально.

- `src/main/index.ts` создаёт окно, трей и сервисы, отправляет состояние таймера каждую секунду.
- `src/main/ipc.ts` принимает вызовы из интерфейса и передаёт их сервисам.
- `src/preload/index.ts` публикует ограниченный API как `window.api` через `contextBridge`.
- `src/shared/ipc.ts` описывает каналы, `StudyTrackerApi` и события; `src/shared/types.ts` — доменные типы.
- `src/renderer/src/App.tsx` хранит выбранную вкладку и живое состояние, подписывается на события.
- `src/main/db/database.ts` создаёт таблицы и содержит репозитории. База `studytracker.db`
  находится в каталоге Electron `app.getPath('userData')`, вне исходников.

Обычный путь данных: страница → `window.api` → preload → IPC main → сервис → репозиторий.
Для нового метода API согласованно меняются контракт, preload и обработчик IPC.

## Правила времени и статистики

- Длительность хранится в **секундах**, временные отметки — в **миллисекундах**.
  Суммировать нужно исходные значения; округление относится только к отображению.
- `formatHms` выводит секундный таймер (`01:30:05`); `formatDuration` — полные минуты
  (`1 ч 30 мин`, `45 мин`, `0 мин`, `< 1 мин`). Он не округляет вверх до ещё не достигнутой цели.
- `dayKey` — локальная логическая дата `YYYY-MM-DD` с учётом `resetHour` (по умолчанию 04:00).
  До часа сброса текущим считается предыдущий день. Подписи графика относятся именно к `dayKey`.
- Для календарного дня используется `new Date(year, month - 1, day)`, как в `time.ts`.
  `new Date('YYYY-MM-DD')` интерпретирует строку как UTC и может дать неверный день недели локально.
- Сейчас вся сохранённая сессия относится к логическому дню **её начала**.
  Изменение распределения сессий через границу дня требует отдельной задачи.
- `stats.getDays('week')` возвращает **текущую календарную неделю пн–вс**;
  будущие дни до воскресенья имеют нулевое время. Границу понедельника задаёт
  `weekStartDayKeyFor`, общий для графика и сводных показателей.
  Карточка «Вчера» отдельно использует `stats.getDays('yesterday')`, включая воскресенье в понедельник.
  `last30` — последние 30 дней; `year` — 371 день для выравнивания тепловой карты.
- `stats.getSummary()` / `GoalService.getSummary()` считает календарные недели пн–вс,
  текущий месяц и всё время из `sessionsRepo.dailyTotals()` плюс активная сессия.
  Границы периодов привязаны к текущему логическому дню с учётом `resetHour`.
  `previousWeekSameDaysSec` — предыдущая неделя с понедельника по такой же день недели
  включительно (полные дни; сегодняшний день ещё не окончен).
- Среднее — сумма времени завершённых календарных недель, делённая на их количество
  с недели первой сессии. Первая неделя входит с фактически записанным временем;
  пустые недели между ней и текущей учитываются как нулевые. Текущая неделя исключается.
  До первой завершённой недели `averageWeekSec` равен `null`, в интерфейсе показано «—».
  Эти показатели доступны и при выключенной геймификации; история не ограничена годом.
- Dashboard и прогресс обновляют статистику каждые 5 секунд. Живой таймер и цель получают
  `event:tick` каждую секунду. Активная сессия хранится в памяти до остановки; её время
  добавляют сервисы при расчёте показателей.
- Дашборд выделяет дневную цель и график недели; «Вся статистика» раскрывает показатели
  по периодам, уровень, рекорд серии и число завершённых сезонов. Кнопки переходят к
  существующим вкладкам сессии и прогресса. Общая тёмная палитра задана в `assets/main.css`.
- Сезон автоматически соответствует текущему календарному месяцу логического дня:
  с первого по последнее число, с переключением в `resetHour`. Его цель — сумма дневных
  целей будней и выходных за весь месяц; уже записанные занятия этого месяца учитываются.
  Изменение дневных целей пересчитывает текущий месяц, цели завершённых сезонов сохраняются.
  Старый произвольный активный сезон архивируется без удаления данных. Пропущенные месяцы
  без запуска приложения не создаются задним числом. `completedSeasonCount` считает
  завершённые календарные сезоны, включая не достигшие цели, без текущего и архивных.
  Ручных методов запуска и завершения сезона в IPC больше нет. Нулевая цель не выдаёт награду.
- Общее время за всё время уже доступно в `GamificationSnapshot.level.totalSec`
  и показано на странице прогресса. Источник — сохранённые сессии плюс активная сессия.
- Достижения описаны в `MILESTONE_DEFS` в `GamificationService.ts`, полученные сохраняются
  в `milestone_unlocks`. При остановке сессии `event:milestone` вызывает тост в `App.tsx`.
  Пороги: 1/5/10/25/50/100/250 часов, серии 3/7/14/30 зачётных дней и цель сезона.
  `MilestoneStatus.currentValue` / `targetValue` задают прогресс: дни для серии, секунды
  для времени и сезона. При отсутствии сезона цель равна `null`. Незавершённая серия показывает
  текущую длину; награда выдаётся по лучшей серии и сохраняется после её обрыва.
  Уже полученные награды и даты не пересчитываются. Новые пороги учитывают всю старую историю.
- Поздравление с новым уровнем проверяется в `App.tsx` каждые 5 секунд и при возвращении
  фокуса/видимости окна. Тост показывается только в видимом активном окне, на любой вкладке.
  `settings.lastSeenLevel` хранит последний показанный уровень в SQLite: при перезапуске
  повторов нет, рост в фоне показывается при возвращении одним тостом о последнем уровне.
  При первом запуске функции текущий уровень запоминается без поздравления за старый прогресс.
  При выключенной геймификации уровень не отмечается просмотренным и тост не показывается.

## Проверка изменений

Команды запускаются из корня проекта через уже установленные зависимости:

```powershell
node ./node_modules/typescript/bin/tsc --noEmit --incremental false --composite false -p tsconfig.web.json
node ./node_modules/typescript/bin/tsc --noEmit --incremental false --composite false -p tsconfig.node.json
node ./node_modules/eslint/bin/eslint.js src/shared/time.ts src/renderer/src/pages/DashboardPage.tsx src/renderer/src/pages/SessionPage.tsx
```

Для ESLint подставляй изменённые файлы. `--composite false` позволяет проверить проект
без обновления файлов `.tsbuildinfo`. Проверки запускаются встроенным раннером Node.js:

```powershell
node --test tests/level-up-toast.test.mjs tests/stats-summary.test.mjs tests/milestone-progress.test.mjs
```

`level-up-toast.test.mjs` проверяет `App.tsx` с подменёнными IPC, событиями окна и таймерами.
`stats-summary.test.mjs` проверяет расчёты `GoalService` с подменёнными временем и репозиторием.
`milestone-progress.test.mjs` проверяет пороги достижений, серии, месячные сезоны, границы
месяца/года, час сброса, изменение целей, старые сезоны и сохранение наград.
Все наборы работают без запуска Electron и не обращаются к пользовательской базе.
Если локальный инструмент отсутствует, сообщи об этом; установка зависимостей — отдельная задача.

Для изменений дат и длительности проверяй: пустую историю, менее минуты, границы минуты и часа,
выходные, переход месяца/года, время до `resetHour` и активную сессию. Для интерфейса полезны
минимальный размер окна 1100 × 600 и наведение на оба сегмента графика.

Не читай и не изменяй файлы `.env` и их варианты. Управление браузером или приложением
через Computer Use требует отдельного разрешения пользователя перед использованием.
